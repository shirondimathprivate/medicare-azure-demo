# MediCare
A Java Servlet and JSP medical appointment management coursework project. Includes clinic scheduling, patient management, billing and a patient portal. Based on the supplied project snapshot from [the coursework repository](https://github.com/IT26100841/medicare-app-OOP-Project).

## Build
Use a JDK 11+ and Maven. Run `mvn clean package`. Tests run during packaging. The Java 11 WAR is written to `target/medicare-app.war`. Deploy to Apache Tomcat 9.

## Azure student demo
Use the existing Linux Web App shiron-medicare-demo in rg-medicare-demo (East Asia). App Service environment variables can be configured under Settings. For the included file-backed demonstration, set MEDICARE_DATA_DIR to /home/medicare-data and MEDICARE_ADMIN_PASSWORD to a private initial password before first use. Sign in as admin. Use synthetic records only. Existing accounts keep their passwords when the app restarts.

With Azure CLI authenticated to the student subscription, run from the project directory:
```sh
az webapp deploy --resource-group rg-medicare-demo --name shiron-medicare-demo --type war --src-path target/medicare-app.war
```
The GitHub build workflow also provides the WAR as a downloadable artifact. Azure Deployment Center can be connected separately if automatic deployments are wanted.

## MySQL mode
Import database/schema.sql into a new empty MySQL database. This is the structure from the supplied dump, including indexes and constraints, without exported rows. Populate synthetic records and a staff account before switching modes. Configure MEDICARE_STORAGE=DB, MEDICARE_DB_URL (for a remote TLS endpoint use jdbc:mysql://HOST:3306/medicare_db?sslMode=VERIFY_IDENTITY), MEDICARE_DB_USER and MEDICARE_DB_PASSWORD as app settings, then restart. Supply the account password as a hash generated by com.medicare.util.Passwords.hash. Keep uploaded documents in persistent storage. File-mode accounts are separate from database accounts.
